# API Contract

Base path: `/api/v1`.

Implemented foundation endpoints:

- `GET /health` — process liveness.
- `GET /ready` — database readiness.
- `POST /api/v1/auth/register`
- `POST /api/v1/auth/login`
- `GET /api/v1/vehicles/search`
- `POST /api/v1/quotes`
- `POST /api/v1/bookings`
- `GET /api/v1/bookings/{booking_id}`

Mutation APIs that can create duplicate business effects require `Idempotency-Key`.

Errors follow:

```json
{
  "success": false,
  "error": {
    "code": "VEHICLE_NOT_AVAILABLE",
    "message": "The selected vehicle is no longer available.",
    "request_id": "..."
  }
}
```

OpenAPI is generated by FastAPI at `/docs` and `/openapi.json` in non-restricted environments.

### State and ownership guarantees

Client-side availability is advisory. Booking writes check quote ownership and
expiry, lock the vehicle row and insert a buffered reservation protected by a
PostgreSQL exclusion constraint. Access to customer bookings, KYC evidence
and operator-owned records is scoped in the backend. Provider callbacks do
not automatically confirm unverified KYC or expired bookings.

### Missing operations

Real gateway credentials do not magically enable a payment flow: a verified
provider adapter, hosted checkout, refund paths and reconciliation are still
release blockers. See `docs/IMPLEMENTED_VS_REMAINING.md`.
